# Issue: Inconsistent Availability Display on September 16

## Problem Description

On September 16, there are overlapping time ranges where:
- Some cards show "available court(s)"
- Other cards show "fully booked"
- But they span the same general time period (6:00 AM - 7:00 PM area)

This creates a confusing user experience.

## Root Cause

The issue is in how **predefined time slots** interact with **all possible time ranges** generated by the system.

### Example Scenario

Sample data seeds only these **exact 1-hour bookings**:
- 6:00 AM - 7:00 AM (Court A booked)
- 7:00 AM - 8:00 AM (available)
- 8:00 AM - 9:00 AM (available)

BUT the availability system generates **all possible combinations**:
- 6:00 AM - 7:00 AM → ✗ BOOKED (Court A has exact booking)
- 7:00 AM - 8:00 AM → ✓ AVAILABLE
- 8:00 AM - 9:00 AM → ✓ AVAILABLE
- **6:00 AM - 8:00 AM** → ✗ BOOKED (overlaps with 6-7 booking)
- **6:00 AM - 9:00 AM** → ✗ BOOKED (overlaps with 6-7 booking)  ← This is why you see "Fully Booked"
- **7:00 AM - 9:00 AM** → ✓ AVAILABLE (no overlap)

## The Overlap Detection Logic

The system correctly prevents double-booking by checking:

```
BookedBooking.StartTime < RequestedRange.EndTime   AND
BookedBooking.EndTime > RequestedRange.StartTime
```

### Visualization

```
Existing Booking (6-7 AM):  [===BOOKED===]

Time Range          Overlap Check              Availability
────────────────────────────────────────────────────────────
6-7 AM              6 < 7? YES, 7 > 6? YES     ✗ BOOKED
7-8 AM              6 < 8? YES, 7 > 7? NO      ✓ AVAILABLE
8-9 AM              6 < 9? YES, 7 > 8? NO      ✓ AVAILABLE
6-8 AM              6 < 8? YES, 7 > 6? YES     ✗ BOOKED (OVERLAPS!)
6-9 AM              6 < 9? YES, 7 > 6? YES     ✗ BOOKED (OVERLAPS!)
7-9 AM              6 < 9? YES, 7 > 7? NO      ✓ AVAILABLE
```

## Why This Happens

The system generates **all possible ranges** by combining ANY start time with ANY end time from the predefined slots.

Given these times: `[6:00, 7:00, 8:00, 9:00]`

It creates these ranges:
```
6-7, 6-8, 6-9
7-8, 7-9
8-9
```

Total: 6 ranges (not just 3 from predefined 1-hour slots!)

## Is This a Bug? Yes! 🐛

**Expected Behavior:**
- Users should book only **predefined 1-hour time slots**
- OR at least, availability should be clearer about what's actually bookable

**Current Behavior:**
- System shows ALL POSSIBLE combinations
- Creates confusing "fully booked" messages for time ranges that span a booked slot
- User might see "6-7 booked" and "7-8 available" but "6-8 fully booked"

## Solution: Limit to Predefined Time Slots

We should modify the availability display to:

1. **Option A (Recommended):** Only show predefined 1-hour slots that are in the database
2. **Option B:** Only show consecutive time slots (e.g., 6-7, 7-8 can combine to 6-8, but only if both are available)
3. **Option C:** Show all ranges but with clearer labeling (e.g., "Conflicts with existing booking")
